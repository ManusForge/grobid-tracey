GROBID-FORK · PLANNED FLOW

From a PDF tap to the cited paper

The pipeline starts when the reader taps a citation. It returns the matched paper, candidate probabilities and match evidence.

13 October 2026 · Planned behavior · Implementation and evaluation are pending.

Input: the current PDF, the page, the tap position and the known paper references.

Output: a verified paper or an unresolved result, with the candidate table and source evidence.

  1. Extract the text under the tap

    Use the existing PDF reader to read the tapped text and nearby text. Keep the original text, page and position.

    Input
    PDF identity, page and tap position.
    Output
    Text and its source position.

  2. Check the citation candidate

    Check the text and nearby context for a citation. Stop for ordinary text, reading gestures or taps outside text.

    A bracketed number alone is not proof of a citation. Do not start model processing or a database search for a rejected tap.

    Input
    Text and tap evidence.
    Output
    An admitted citation candidate, or a stopped action.

  3. Find the bibliography entry

    Use GROBID to find the bibliography and read its entries. Match the citation label, authors or year to those entries.

    Use the labels from the displayed PDF. Database order must not change this mapping.

    Keep the matched entry and its source text. Reuse the extracted bibliography for later taps.

    Input
    Citation candidate and current PDF.
    Output
    Candidate bibliography entries and their match evidence.

  4. Collect candidate paper records

    Compare the bibliography entry with the known paper references. Use identifiers, title, authors and year to find candidate records.

    If the paper is not in that list, use the existing catalogue lookup to retrieve its metadata.

    Input
    Bibliography entry and known paper references.
    Output
    Candidate paper records and their metadata sources.

  5. Verify the candidate papers

    Check identifiers, title, authors and year. Use semantic similarity to compare independent descriptions of the reference and each candidate.

    A high similarity score must not override conflicting identifiers. Metadata copied from the reference is not independent verification.

    Input
    Bibliography entry and candidate metadata.
    Output
    Identifier checks, similarity scores and conflicts.

  6. Build the candidate probability table

    Rank the candidates from the match evidence and verification results. Return the estimated probability for each candidate.

    Include a “No known match” result. Do not force a match when the correct paper is missing.

    Keep probability and similarity as separate values. If the probability method is not verified, report all probabilities as unavailable.

    Input
    Candidate records and verification evidence.
    Output
    Ranked candidates and an accepted or unresolved match.

  7. Add a missing paper and return the result

    If the paper exists but the known reference list omits it, record the PDF-supported reference separately.

    If the paper is missing, add its record only after verification. Reuse an existing matching record to prevent duplicates.

    If the match remains uncertain, return an unresolved result. Do not add a guessed paper.

    Return the verified paper to the existing trace action. Keep the source citation and bibliography entry as evidence.

    Input
    Accepted or unresolved match and the current catalogue state.
    Output
    Existing or added paper, reference evidence and the final result.

Candidate table fields

Use one table for each bibliography entry selected by the citation.

FieldMeaning
paper_idThe candidate paper identity, or no identity for “No known match”.
titleThe candidate title from its metadata source.
probabilityThe estimated match probability, or an unavailable value.
semantic_similarityThe separate similarity score and its method.
identifier_checkAgreement, conflict or missing identifiers.
decisionAccepted, unresolved or no known match.

The probability table must identify its method. Available probabilities must total one, including “No known match”.

Reuse GROBID’s existing models and required processing stages. No new GROBID model training is planned.

Evaluate correct links, wrong links, missed citations, false activations and execution time before accepting the flow.
